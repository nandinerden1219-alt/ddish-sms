# Мэдээллийн сан

Компанийн дотоод мэдээллийн Excel хуудсыг орлох, ажилтнууд нэвтрэлгүйгээр хайж, харж, хуулж болох веб апп. Админууд тусдаа удирдлагын самбараас бүх мэдээллийг нэмж, засаж, устгаж болно.

**Stack:** Next.js (App Router) · TypeScript · Tailwind CSS v4 · Supabase (PostgreSQL + Auth) · SheetJS (Excel импорт)

## 1. Суулгах

```bash
npm install
```

## 2. Supabase төслөө үүсгэх

1. [supabase.com](https://supabase.com) дээр шинэ төсөл (project) үүсгэнэ.
2. **Project Settings → API** цэснээс дараах хоёр утгыг авна:
   - `Project URL`
   - `anon public` key

## 3. SQL схем ажиллуулах

1. Supabase Dashboard → **SQL Editor → New query**.
2. Энэ репо дэх [`supabase-schema.sql`](./supabase-schema.sql) файлын бүх агуулгыг хуулж, буулгаад **Run** дарна.

Энэ скрипт дараах зүйлсийг үүсгэнэ:

- `categories`, `information_items`, `information_usage` хүснэгтүүд
- Ашиглалтын статистик бодох `information_popularity` view
- Row Level Security (RLS) — нийтийн хэрэглэгч зөвхөн идэвхтэй өгөгдлийг унших, зөвхөн нэвтэрсэн (админ) хэрэглэгч нэмэх/засах/устгах эрхтэй
- `announcements` — админы мэдэгдэл (нүүр хуудасны дээр харагдах пост)
- `category_groups` — хажуугийн цэсний бүлгүүд (ангиллууд эдгээрээс салаална)
- `useful_links` — хэрэгтэй линкүүд
- Бодит 10 ангилал + 66 мэдээлэл болон нэг угтах мэдэгдэл (админ хэсгээс засаж/устгаж болно)

Файл бүхэлдээ **дахин ажиллуулахад аюулгүй** — байгаа өгөгдөл давхардахгүй. Схемийг өмнө нь ажиллуулсан бол зөвхөн шинэ хэсгийг [`supabase-migrations/`](./supabase-migrations/) доторх файлаас ажиллуулж болно.

## 4. Орчны хувьсагч (environment variables)

`.env.example`-ийг хуулж `.env.local` нэрээр үүсгэнэ:

```bash
cp .env.example .env.local
```

Дараа нь 2-р алхамд авсан утгуудаа бичнэ:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

> `anon` түлхүүр нь public-д зориулагдсан бөгөөд RLS-ээр хамгаалагдсан тул frontend дээр ашиглахад аюулгүй. `service_role` түлхүүрийг **хэзээ ч** frontend код дотор бүү ашигла, environment-с гадуур бүү задруул.

## 5. Локал орчинд ажиллуулах

```bash
npm run dev
```

Дараа нь [http://localhost:3000](http://localhost:3000) — нийтийн хуудас нэвтрэлгүйгээр нээгдэнэ.

## 6. Админ бүртгэл үүсгэх

Энэ апп өөрөө бүртгүүлэх (sign-up) хуудасгүй — админ эрхийг зөвхөн Supabase Dashboard-с зохицуулна:

1. Supabase Dashboard → **Authentication → Users → Add user**.
2. Имэйл + нууц үгээ оруулаад **Auto Confirm User**-ийг идэвхжүүлж хадгална (email баталгаажуулалт алгасна).
3. [http://localhost:3000/admin/login](http://localhost:3000/admin/login) хаягаар нэвтэрнэ.

Нэвтэрсэн дурын Supabase Auth хэрэглэгч бүр админ эрхтэй гэж тооцогдоно (RLS `authenticated` role дээр суурилсан) — тиймээс зөвхөн итгэмжлэгдсэн хүмүүст л бүртгэл үүсгэнэ.

Нэвтэрсний дараа `/admin/settings` хуудаснаас нууц үгээ солих боломжтой.

## Ажилтнуудад: хамгийн хурдан ашиглах арга

Нүүр хуудас нээгдэхэд хайлтын талбар шууд идэвхтэй байна.

| Үйлдэл | Хэрхэн |
| --- | --- |
| Хайх | Шууд бичнэ — кирилл ч, латин ч болно (`сунгалт` = `sungalt`), үгийн дараалал хамаагүй |
| Эхний үр дүнг хуулах | **Enter** |
| Дурын мэдээлэл хуулах | Мессежийн хайрцаг дээр **дарах** эсвэл «Хуулах» товч |
| Хайлт руу очих | `/` эсвэл `Ctrl/⌘ + K` |
| Хайлтыг цэвэрлэх | `Esc` |
| Сүүлд хуулснаа дахин хуулах | Дээд талын «Сүүлд хуулсан» мөрөөс нэг дарна |

Хуулахад мөрийн хуваалт (line break) хэвээр хадгалагдана — SMS/чат руу шууд буулгаж илгээж болно.

## Хажуугийн цэс: бүлэг → ангилал

Нүүр хуудасны хажуугийн цэс мод хэлбэртэй:

```
Бүх мэдээлэл
Пост                  ← админы мэдэгдлүүд
Хэрэгтэй линк         ← дотоод систем, банк, сошиал суваг
ЗААВАР
▾ Сунгалт хийх заавар
    • Сунгалттай холбоотой
    • Данс, цэнэглэлт
    • …
▾ SMS заавар
    • Админ дугаарын бүртгэл
    • Кино ба контент
    • …
```

`/admin/categories` дээр бүлэг нэмэх/нэрлэх/дараалал солих, ангилал бүрийг аль бүлэгт харьяалуулахаа сонгоно. Бүлэггүй ангилал «Бусад ангилал» дор харагдана. Бүлэг дээр дарвал доторх бүх ангиллын мэдээлэл ангиллаар нь салаалж харагдана.

## Хэрэгтэй линк

`/admin/links` — нэр, URL, тайлбар. Нүүр хуудасны «Хэрэгтэй линк» хэсэгт «Нээх» (шинэ цонх) ба «Линк хуулах» товчтой картаар харагдана.

## Админы мэдэгдэл (пост)

`/admin/announcements` — ажилтнуудад зориулсан мэдэгдэл нийтэлнэ. Мэдэгдэл нүүр хуудасны хамгийн дээр огноотойгоо харагдана.

- **Түвшин**: Мэдээлэл / Анхааруулга / Яаралтай (өнгөөр ялгагдана)
- **Тогтоох**: чухал мэдэгдлийг жагсаалтын дээр барина
- **Дуусах өдөр**: заасан өдрөөс хойш нүүр хуудаснаас автоматаар алга болно
- **Нуух / Устгах**: түр нуух эсвэл бүрмөсөн устгах
- Агентууд мэдэгдлийн текстийг «Текстийг хуулах» товчоор шууд хуулж чадна (хэрэглэгч рүү илгээх бэлэн хариу оруулахад тохиромжтой)

## 7. Excel-с өгөгдөл импортлох (сонголтоор)

`/admin/import` хуудаснаас `.xlsx`, `.xls`, `.csv` файл сонгож:

1. Баганаа урьдчилан харах
2. `Category` / `Title` / `Message` / `Additional Information` баганатай харгалзуулах
3. Импортлох — амжилттай/алдаатай тоог харуулна

`Category` баганад орсон нэр Supabase-д байхгүй бол шинэ ангилал автоматаар үүснэ.

## 8. Production deploy (жишээ нь Vercel)

1. Репозиторыг GitHub-т push хийнэ.
2. [vercel.com](https://vercel.com) дээр импортолно.
3. Project Settings → Environment Variables хэсэгт `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`-г нэмнэ.
4. AI боломжуудад (Оношилгоо, Nandia AI, Nandia-д заах) `GEMINI_API_KEY`-г нэмнэ ([aistudio.google.com/apikey](https://aistudio.google.com/apikey), төлбөрийн тохиргоо холбоогүй төслийн түлхүүр бол үнэгүй). `NEXT_PUBLIC_` угтвар бүү тавь — түлхүүр зөвхөн серверт байна.
5. Deploy. Орчны хувьсагч нэмсэн/сольсон бол **Redeploy** хийнэ — хуучин deploy шинэ утгыг авахгүй.

Ямар ч хост дээр deploy хийж болно (Netlify, self-hosted Node сервер гэх мэт) — зөвхөн дээрх орчны хувьсагчдыг тохируулах шаардлагатай.

## Төслийн бүтэц

```
src/
  app/
    page.tsx                 Нийтийн нүүр хуудас (Server Component)
    admin/
      login/                 Админ нэвтрэх
      (dashboard)/           Хамгаалагдсан админ хэсэг
        page.tsx              Dashboard
        information/          Мэдээлэл удирдах
        categories/           Ангилал удирдах
        popular/              Түгээмэл мэдээлэл сонгох
        import/                Excel импорт
        settings/              Тохиргоо
  components/
    public/                  Нийтийн UI бүрэлдэхүүн (хайлт, карт, ангилал)
    admin/                   Админ UI бүрэлдэхүүн (хүснэгт, форм)
  lib/
    supabase/                Browser/server Supabase client-ууд
    search.ts, copyItem.ts, recent.ts, categoryIcons.ts, utils.ts
  types/                     TypeScript төрлүүд
  proxy.ts                   Route хамгаалалт (Next.js 16 middleware/proxy)
supabase-schema.sql          Бүрэн SQL схем + RLS + жишээ өгөгдөл
```

## Аюулгүй байдал

- Нийтийн хэрэглэгч зөвхөн идэвхтэй (`is_active = true`) өгөгдлийг унших боломжтой — энэ нь Supabase RLS-ээр давхар баталгаажсан бөгөөд зөвхөн frontend логикоос хамаардаггүй.
- Мэдээлэл нэмэх/засах/устгах бүх үйлдэл зөвхөн нэвтэрсэн (authenticated) хэрэглэгчид зөвшөөрөгдөнө.
- `/admin/*` route бүрийг Next.js proxy (`src/proxy.ts`) session шалгаж, нэвтрээгүй бол `/admin/login` руу шилжүүлнэ.
- `service_role` түлхүүр хаана ч ашиглагдаагүй бөгөөд орчны хувьсагчаас гадуур хадгалагдахгүй.
